# Flex

Приложение для семьи: задачи, календарь, покупки, заметки, рецепты, накопления,
хотелки, чаты и уведомления. Живёт как PWA, ставится на домашний экран,
работает через HTTPS по адресу <https://veheys.online>.

## Что внутри

| Раздел | Что умеет |
|---|---|
| Задачи | доска с колонками, перетаскивание, приоритет, срок, семейные задачи, назначение исполнителя и уведомление автору о готовности |
| Календарь | месяц, двойной тап по дате, разбор даты и времени прямо из названия, семейная видимость, три напоминания |
| Покупки | список, категории, семейный список, отметка «куплено» |
| Заметки | текст, картинки, аудио, поиск |
| Рецепты | импорт по ссылке, ингредиенты, семейная видимость |
| Накопления | цели и движения денег, семейная видимость |
| Хотелки | списки, подарки, получатели, семейная видимость |
| Чаты | переписка с шифрованием в браузере |
| Семья | приглашения по адресу, роли, общие списки |
| Профиль | аватар, дата рождения, Telegram, уведомления |

## Стек

- **Клиент** — React, TypeScript, Vite, Tailwind, `vite-plugin-pwa`, Workbox,
  `dnd-kit`, `framer-motion`.
- **Сервер** — Node.js, Express, TypeScript, Prisma, PostgreSQL, `web-push`,
  `zod`, `helmet`.
- **Деплой** — GitHub Actions, Docker, nginx, xray на 443.

## Как запустить локально

Нужен Node.js 20+ и PostgreSQL.

```bash
# база
docker run -d --name flex-postgres \
  -e POSTGRES_DB=flexdb -e POSTGRES_USER=flex -e POSTGRES_PASSWORD=... \
  -p 5432:5432 postgres:16-alpine

# переменные окружения
cp server/.env.example server/.env   # заполнить DATABASE_URL и JWT_SECRET
cp .env.example .env

# зависимости и база
cd server && npm install && npm run db:generate && npm run db:push && cd ..

# всё сразу: сервер на 3001, клиент на 5173
npm install && npm run dev
```

Продакшен-сборка:

```bash
npm run build          # сервер (tsc + проверки) и клиент
npm start              # только сервер, нужен собранный client/dist
```

## Проверки

```bash
cd server
npm run build     # кодировка, tsc, пять проверок кода, юнит-тесты
npm test

cd ../client
npm test                  # рендер приложения и поведение запросов
npm run check:render      # задеплоенный бандл, без сессии
npm run test:prod         # то же с адресом явно
npm run test:prod:auth    # все экраны с сессией, по одному прогону
```

`render-check` поднимает настоящий бандл в jsdom. Он проверяет не только то,
что приложение не упало, но и что страница отрисовала своё содержимое: пустое
состояние не проходит за успех. Именно эта проверка ловит белый экран — ошибку
на этапе рендера, которую не видно ни по HTTP-кодам, ни по сборке.

Живые наборы (нужен запущенный стенд):

```bash
node smoke.mjs https://veheys.online/api
node bug-hunt.mjs https://veheys.online/api
node security-check.mjs https://veheys.online/api
```

## Переменные окружения

Обязательное:

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | подключение к PostgreSQL |
| `JWT_SECRET` | подпись токенов; при установке из примера генерируется автоматически |

Дополнительное:

| Переменная | Зачем |
|---|---|
| `CLIENT_URL` | origin для CORS |
| `TELEGRAM_BOT_TOKEN` | вход и привязка Telegram |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | push-уведомления; генерируются деплоем при первом запуске и дальше не меняются |
| `PORT` | порт API, по умолчанию 3001 |

Почты нет: SMTP удалён, приглашения в семью приходят уведомлением в приложении
и по��ушу, поэтому приглашать можно только зарегистрированного человека.

## Безопасность

- Пароли — bcrypt, 12 раундов. Неизвестный адрес сравнивается с фиктивным
  хешем, чтобы время ответа не выдавало, существует ли аккаунт.
- Пять неудачных попыток — блокировка аккаунта.
- JWT с закреплённым алгоритмом и отдельным `typ` для access и 2FA-токенов.
  `tokenVersion` отзывает все выданные токены разом.
- Refresh-токен хранится как хеш и ротируется: повторное использование
  старого не проходит.
- Смена почты требует текущий пароль — иначе можно было бы переписать адрес на
  чужой и забрать приглашение в чужую семью.
- Каждая запись проверяет владельца: чужие задачи, заметки, списки и чаты
  недоступны ни на чтение, ни на запись.
- Исполнитель задачи может только перемещать её по колонкам автора; менять
  заголовок, описание, приоритет и срок ему нельзя.
- Загрузки ограничены типами и обслуживаются из одной папки: выход за её пределы
  отсекается.
- Через API нельзя выйти в сеть от сервера: адреса проверяются, включая
  внутренние и IPv4-в-IPv6 (DNS rebinding — известное ограничение).
- Ограничения по частоте: отдельно на регистрацию, вход, вход через сервис,
  импорт рецептов, загрузку и поиск по чатам.

## Уведомления

Push работает через web-push. Ключи VAPID генерируются деплоем один раз.

- Задача, назначенная человеку: «Вам поставили задачу от …» с названием и
  сроком.
- Задача, доведённая исполнителем до колонки «Готово»: автору «Задача готова»
  с именем исполнителя.
- Событие: три напоминания — за сутки («Завтра, 19:46»), за час («Через час,
  19:46») и за пять минут («Встреча — 19:46»).

Время считается в часовом поясе, где событие было создано, поэтому напоминание
не приезжает на несколько часов позже. Если событие перенесли — напоминания
сбрасываются.

В профиле есть кнопки «Проверить доставку» и «Состояние доставки»: они
показывают, знает ли сервер об этом устройстве и была ли последняя отправка.
Без этого «уведомления включены» и «сервер знает о вас» — разные вещи, а
отличить их было нечем.

## Устройство

```
client/           React-клиент, PWA и service worker
server/           Express API, Prisma, юнит-тесты
scripts/          проверки nginx
nginx/            конфиг vhost
.github/workflows/deploy.yml   деплой по пушу в main
```

Service worker кэширует оболочку, но навигация всегда сначала идёт в сеть:
иначе закэшированный `index.html` ссылается на файлы, которые деплой уже
удалил, и телефон показывает пустую страницу.

## Деплой

Пуш в `main` запускает workflow: сборка клиента, обновление схемы базы,
сборка образа при изменении сервера, перезапуск контейнера, заголовки
безопасности и перезагрузка nginx.

nginx перезагружается, а не перезапускается: xray проксирует 443 в nginx, и
перезапуск разорвал бы чужой VPN.

Тайминги последней фазы публикуются в `/_timing.txt`.

## Полезное

```bash
bash check.sh          # диагностика сервера, ничего не меняет
bash deploy.sh         # ручной деплой (легаси, основной путь - CI)
```

На сервере: `docker compose logs -f server`, `systemctl status nginx`,
`docker logs flex-postgres`.
